# Цели проекта
1. симулировать данные, похожие на данные в закрытом контуре целевого заказчика, - для отработки методов их обработки в открытом контуре разработки (и переиспользования подходов)
2. сделать свой эмбеддинг, заточенный под данный корпус технических комментариев
3. проверить качество векторизации на кластеризации и поиске похожих
4. переиспользовать код эмбеддинга в контуре реальных данных
# Что делает
* на основе yaml-описания предметной области генерит короткие технические комментарии службы техподдержки по обращениям абонентов в техподдержку - стандартное поле тикета техподдержки телеком оператора
* далее строит свой собственный ранжированный словарь для семантической векторизации комментариев
* векторизация по словарю методом BoW - порядок токенов не важен
* SVD и KMeans по косинусной близости нормализованных SVD-векторов
# Как планируется использовать
обычные трансформеры и эмбеддинги общеязыковых моделей (обученные и доступные в интернете) дают плохую метрику для кластеризации по косинусной схожести текстовых комментариев техподдержки - эмпирический результат.  Поэтому я хочу обучать свой эмбеддинг - далее буду подбирать слои модели и писать цикл обучения по эпохам на корпусе, который сгенерит данный генератор
# Структура папок
* `notebooks` - запускающие блокноты - пронумерованы в порядке следования процесса от исходных текстов к кластеризации
* `src` и `src.tokenizer` - модули кода на питоне (конфигурационные переменные, функции и классы)
* `dictionaries`, `topology`, `language` - yaml-дефиниции параметров генерации текстов из предметной области (не нужны при переносе только кода векторизации текстов, если данные уже есть)
